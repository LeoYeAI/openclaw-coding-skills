# Verification Matrix

## Documentation or prompt changes

Use diff inspection and any format validation that applies.

## Bug fixes

Use a before-and-after proof, targeted test, or runtime trace.

## Features

Use the combination of targeted tests and runtime checks that best proves the new behavior.

## Refactors

Use behavior-preserving evidence such as existing tests, typecheck, lint, and focused diff review.

## Review standard

A verification step only counts if it would convince a skeptical engineer.
