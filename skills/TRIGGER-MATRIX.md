# Trigger Matrix

This file maps common developer requests to the most likely skills.

## Workflow Triggers

### `openclaw-dev-workflow`

Use for broad requests such as:

- build this feature
- implement this end to end
- fix this across the codebase
- help me ship this safely
- handle this coding task properly

### `spec-for-openclaw`

Use for requests such as:

- help me define this feature first
- write a spec before we code
- turn this idea into an implementation target
- clarify scope and acceptance criteria

### `plan-for-openclaw`

Use for requests such as:

- break this into tasks
- make a plan
- split this into steps
- figure out the implementation order

### `build-for-openclaw`

Use for requests such as:

- implement this
- make the code change
- add this behavior
- wire this up
- patch this without rewriting everything

### `test-for-openclaw`

Use for requests such as:

- verify this works
- what tests should we add
- prove this change is safe
- what evidence do we need before merge

### `review-for-openclaw`

Use for requests such as:

- review this change
- audit this PR
- look for bugs or regressions
- sanity-check this implementation

### `ship-for-openclaw`

Use for requests such as:

- are we ready to ship
- close this out cleanly
- prepare final handoff
- make sure release notes and risk are covered

## Specialist Triggers

### `debug-for-openclaw`

Use for requests such as:

- this test is failing
- the build broke
- this works sometimes and I do not know why
- help me debug this
- logs show an error but I do not know the cause

### `security-for-openclaw`

Use for requests such as:

- is this secure
- review auth or permissions
- we are touching secrets or tokens
- this code calls external APIs or handles user input
- check the trust boundaries here

### `frontend-for-openclaw`

Use for requests such as:

- build this UI
- fix this page or component
- this interaction is broken
- make this responsive
- verify the browser flow

### `docs-for-openclaw`

Use for requests such as:

- update the docs
- write the operational notes
- capture this decision
- document the setup or workflow change

### `deploy-for-openclaw`

Use for requests such as:

- deploy this
- prepare this for production
- update config and ship it
- what is the rollback plan
- check release readiness

### `refactor-for-openclaw`

Use for requests such as:

- clean this code up
- simplify this without changing behavior
- this module is getting hard to maintain
- reduce duplication here
- refactor this carefully
