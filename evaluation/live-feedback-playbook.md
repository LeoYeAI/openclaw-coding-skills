# Live Feedback Playbook

Use this playbook after recording real-task validation.

## Step 1: Classify the live-task outcome

Ask:

- Was the first trigger correct?
- Was the first trigger defensible but incomplete?
- Did the task require a second specialist skill earlier than expected?
- Did the task expose a missing ambiguity boundary?
- Did the task expose missing reference support inside an otherwise correct skill?

## Step 2: Choose the repository update target

### Update a skill description

Do this when the first trigger was wrong or too weak.

### Update the trigger matrix

Do this when the skill is right, but the boundary guidance is under-explained.

### Add an example task

Do this when the real phrasing is common and not represented yet.

### Add an ambiguity case

Do this when the request sits on a boundary and a competing skill nearly won.

### Add reference support

Do this when the skill triggered correctly but execution guidance ran thin during the task.

## Step 3: Record the repository action

For each real task, write:

- what happened
- what repository asset should change
- what the smallest useful change is
- what nearby boundary should be re-checked after the update

## Rule

Do not jump to broad rewrites from one task. Prefer one small repository adjustment backed by one specific live observation.
