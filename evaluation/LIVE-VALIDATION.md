# Live Validation

This document defines how to record real coding-task validation runs.

Static samples test trigger design quality. Live validation checks whether the skill system holds up when attached to real work.

## What To Record Per Task

- task label
- raw user request
- likely first-trigger skill
- whether that first trigger felt correct
- whether a second skill became necessary during execution
- what ambiguity or weakness appeared
- what repository asset should be updated next

## Goal

Use 3 to 5 real tasks at a time. Prefer diversity over volume:

- one implementation task
- one review or testing task
- one high-risk task such as security or deploy
- one UI or interaction task when relevant

## Rule

Do not treat a correct first trigger as total success. Also record whether the skill guidance stayed useful as the task evolved.
