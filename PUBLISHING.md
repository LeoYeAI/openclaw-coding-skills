# Publishing

Use this checklist before publishing the repository publicly.

## Pre-Publish Checks

- confirm README reflects the current skill set
- confirm installation and adoption guides are current
- confirm evaluation and ambiguity files do not contain misleading labels
- confirm no secrets, private prompts, or internal-only notes exist in examples or references
- confirm version and release notes are aligned

## Publish Story

When describing the repository publicly, lead with:

- this improves engineering behavior, not base model weights
- this is designed for OpenClaw workspaces
- this is part of the MyClaw.ai open ecosystem
- this includes both skills and tuning infrastructure

## Post-Publish Maintenance

After release, treat these as living assets:

- trigger descriptions
- example tasks
- ambiguity cases
- evaluation datasets
- deep references for high-risk skills
