# Versioning

This repository uses simple semantic intent rather than rigid package-manager semantics.

## Minor Version Bumps

Increase the minor version when the repository gains meaningful new capability, such as:

- new skills
- new deep reference sets
- new evaluation layers
- new adoption or tuning infrastructure

## Patch Version Bumps

Increase the patch version when improving:

- skill descriptions
- trigger examples
- evaluation samples
- documentation clarity
- small reference refinements

## Major Version Bumps

Increase the major version only when:

- repository structure changes substantially
- skill names change incompatibly
- adoption guidance or tuning assumptions are fundamentally reworked

## Practical Rule

Version changes should reflect operational meaning for adopters, not just file count changes.
